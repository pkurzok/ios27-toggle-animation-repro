# iOS 27: `Toggle` drops the transaction from `Binding.animation(_:)`

> **Fixed in iOS 27.2 beta 1** (FB24396602). The rest of this README describes the original
> iOS 27.0 behaviour and is kept for reference; this repository is archived.

A minimal SwiftUI repro for a regression in iOS 27.0 (simulator build `24A5408d`).

A state write initiated by a `Toggle` bound with `Binding.animation(_:)` no longer carries its
animation transaction into the resulting view update. The switch thumb still animates, but every
view that depends on the written value updates in a single frame.

The regression is specific to `Toggle`'s write path, not to the binding:

| Write path | iOS 26.5 / macOS | iOS 27.0 |
| --- | --- | --- |
| `Toggle` + `$flag.animation(.snappy)` | animates | **jumps in one frame** |
| `Button` + `withAnimation(.snappy)` | animates | animates |
| `Toggle` + `withAnimation` inside a custom `Binding` setter | animates | animates |
| Programmatic write through the *same* `$flag.animation(.snappy)` binding | animates | animates |

That last row is the interesting one: the binding itself is fine. Only the `Toggle`'s own write
loses the transaction.

## Running it

```bash
git clone https://github.com/pkurzok/ios27-toggle-animation-repro
cd ios27-toggle-animation-repro
open ReproApp.xcodeproj
```

Run on an iOS 27 simulator, then tap each of the three controls in turn. All three flip the same
`@State` flag, which changes both the membership and the frames of a `ForEach` of bars.

- **"Binding.animation (broken on iOS 27)"** — the bars jump. Expected: they resize and the extra
  bar inserts over ~0.3 s.
- **"withAnimation in a Button (works)"** — animates.
- **"withAnimation in the setter (works)"** — animates. This is the workaround.

Set `demonstratesProgrammaticWrite` to `true` in `Sources/ToggleBindingAnimationRepro.swift` to
watch a programmatic write through the same `$flag.animation(.snappy)` binding animate correctly.

Run the same build on an iOS 26.5 simulator and all three animate.

## Environment

- iOS 27.0 simulator, runtime build `24A5408d` (iPhone 17)
- Xcode 27.0 (`27A5237l`), macOS 26
- Not reproducible on iOS 26.5 (same binary) or on macOS
- Not mentioned in the iOS 27 or Xcode 27 release notes; no forum reports found as of 2026-08-18

A behaviourally analogous regression (`Form` row animations) appeared in the iOS 26 beta 3 seed and
was fixed one beta later: <https://developer.apple.com/forums/thread/793278>

## Workaround

Animate inside the setter, so the transaction is applied synchronously with the write:

```swift
Toggle("Put money aside", isOn: Binding(
    get: { showsSavings },
    set: { newValue in withAnimation(.snappy) { showsSavings = newValue } }
))
```

This behaves identically on older releases, so it is safe to adopt unconditionally.

## Where this came from

Found while animating a Sankey diagram in [SankeyKit](https://github.com/pkurzok/SankeyKit), whose
marks are added and removed by a result-builder `if`. The single-frame jump reproduced on both the
current and the preceding commit of that project, which ruled out an app-side change; a
frame-by-frame comparison of screen recordings driven by XCUITest taps confirmed the difference
between the two write paths.
